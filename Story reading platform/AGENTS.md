# Project working instructions

Read PROJECT_CONTEXT.md, PROJECT_PLAN.md and ARCHITECTURE.md before project work. The source proposal is WEBSITE DEVELOPMENT CONTRACT.pdf; follow its agreed feature scope and record ambiguities rather than silently changing requirements.

- The user authorized Phase 1 implementation and sequential verification. Read the current context and milestone report; keep external checks and client acceptance distinct from local test completion. Begin later phases only when directed.
- Keep the MERN stack: Next.js/React frontend, separate Express/Node API, MongoDB, versioned REST. Backend business logic must remain reusable by a future native client.
- Follow the three phases and subphases in PROJECT_PLAN.md. Distinguish planned, implemented, tested, delivered and accepted work.
- Enforce full-chapter authorization server-side from the first implementation. No private chapter text in anonymous HTML, hydration/RSC, public APIs, metadata or shared caches.
- Reward unlocks require verified provider server-to-server callbacks and durable account records. Never trust a browser completion event as proof.
- Preserve milestone source handovers, client-owned provider accounts and the agreed MVP exclusions. Do not use the client's GitHub account directly.
- Keep credentials and the contract's personal/banking data out of code, planning notes, logs and delivery archives.
- Use tests appropriate to changes, prioritizing access control, reward integrity, content leakage and critical reading/publishing journeys.
- Update PROJECT_CONTEXT.md after meaningful work with decisions, progress, verification, blockers and the next step.
